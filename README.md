# 公交接驳满意度调查 · 两版均分差值复核页

更正后的满意度调查需要估计「更正表均分 − 原表均分」及其抽样波动。本服务提供一个
Flask 网页：上传原表 CSV → 入库（SQLite 原样保留）→ 按户补录 / 改分 / 移除 →
**核实并改配两表住户** → 固定种子的 1000 轮泊松自助 → 展示未加权均分差、有效轮数与
轮差值的 2.5% / 97.5% 分位。

## 一键启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

- 数据库落在命名卷 `survey-data`（容器内 `/data/survey.db`），容器重建后数据仍在。
- 生产环境请修改 `docker-compose.yml` 中的 `SECRET_KEY`。
- 本地无 Docker 时：`pip install -r requirements.txt` 后
  `gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 wsgi:app`
  （SQLite + 单进程多线程；每请求独立连接）。

## CSV 格式

UTF-8 文本（允许 BOM），每行两列：`住户号,评分`。

- 住户号：非空、全表唯一；
- 评分：0～10 的整数；
- 首行若是表头（第二列不是整数）会自动识别并跳过；空行忽略；
- 任一记录非法则整次上传被拒绝，数据库不做任何改动。

## 页面操作与展示

1. **上传原表**：原表写入 `original_scores` 后不再被任何功能修改；更正表
   `corrected_scores` 初始化为完全相同的副本，并按相同编号一一配对。
2. **按户更正**：输入住户号，选择「补录 / 改分 / 移除」（移除不需要评分）。
   另有单户查询和「重置更正表为原表」。
3. **改配（核实原表号 ↔ 更正表号）**：每行填一组合法配对，可一次提交多组。
   - 两表各自的编号与评分**都保留**，改配只改「权重取自哪一户」；
   - 可**在同一单内对调**（如 `B↔A` 一次提交）；
   - 因本单失去伙伴、又没有在本单获得新配对的住户，**自动解配**；
   - 原表号查不到、更正表号查不到、或同一侧编号重复，**整单退回**，不做任何改动；
   - 也可单独「解配该更正户」。
4. **单户查询**：显示该户两版评分；查到更正户时显示其**配对的原表号**（附该原表
   评分），未配对则标明「未配对（使用固定独立权重）」。
5. **估计结果**（只读 `meta` 与两张轮次汇总表，不碰住户明细表）：
   - 两表户数与未加权均分；
   - 未加权均分差（更正 − 原）；
   - 有效轮数 / 1000，以及被跳过的轮数（任一侧权重合计为 0 即跳过）；
   - 轮差值的 2.5% 与 97.5% 分位（type-7 线性插值，与 numpy 默认定义一致）；
   - 无法计算时显示明确原因（未上传、更正表为空、全部轮次权重合计为零等）。

## 权重规则（与需求逐条对应）

- 固定种子（`app/bootstrap.py` 中 `MASTER_SEED = 20261123`），共 **1000 轮**；
- 每轮每户独立抽取均值为 1 的泊松权重 `Pois(1)`（Knuth 算法）；
- 权重是 `(种子, 轮次, 住户号)` 的确定性函数（BLAKE2b 取 64 位 → SplitMix64），
  因此其他住户的新增、删除、重排都不会改变该户权重，重复运行结果逐位可复现；
- **配对**：更正户沿用其配对原表户的各轮权重（`household_weights(配对原表号)`），
  与更正户自己的编号无关；
- **未配对**：使用固定独立权重
  `independent_household_weights(更正表号)`，它在种子中加了 `independent`
  命名空间，所以**即使编号与原表某户相同，也不共用原表的权重流**；
- 每轮计算
  `d_r = 更正加权均分_r − 原表加权均分_r = Σw·s/Σw（更正） − Σw·s/Σw（原）`，
  任一侧 `Σw = 0` 时该轮跳过。

### 其他操作与配对的交互

| 操作 | 配对行为 |
| --- | --- |
| 改分 | 沿用**生效时**的配对（配对不变，权重不变） |
| 移除更正户 | 同时释放其原表伙伴 |
| 补录 | 仅当同号原表户**空闲**（未被任何更正户配对）时自动配对，否则以独立权重未配对入户 |
| 重新上传 / 重置 | 恢复「同号配对」，汇总同步重建 |
| 旧库（无配对列） | 自动加列并回填：同号原表户记为配对；无同号原表户的旧更正户标记为 `legacy_same_id`，继续用旧的同号权重流；**不重算汇总，旧结果原样沿用** |

## 存储与事务设计

| 表 | 内容 |
| --- | --- |
| `original_scores` | 原表户号 + 评分，上传后只增不改（重新上传时整体替换） |
| `corrected_scores` | 更正表户号 + 评分 + `orig_id`（配对原表号，NULL 为未配对）+ `weight_mode` |
| `orig_rounds` / `corr_rounds` | 每轮的权重合计 `weight_total` 与加权评分合计 `weighted_sum`（各 1000 行） |
| `meta` | 两表户数、评分合计、迁移标记等标量 |

- 每次按户更正只重算**该户**的 1000 个轮次贡献，其余户数据不读取；
- 改配先只读编号/配对元数据，确定哪些户的配对真的变了，再**只读这些变化户的评分**
  并重算其贡献；
- 更正表明细与 `corr_rounds` 汇总在**同一个 SQLite 事务**内提交，任何失败都回滚，
  页面继续展示上一版结果并提示原因；
- 分析查询仅访问汇总表与 `meta`，满足「查询只读汇总」。

## 目录结构

```
app/
  __init__.py      Flask 工厂与路由（上传 / 更正 / 改配 / 解配 / 重置 / 查询 / 健康检查）
  bootstrap.py     固定种子确定性泊松权重（配对共用流 + 未配对独立流）
  csv_io.py        CSV 解析与校验
  db.py            SQLite 建表与旧库迁移、入库、按户更正、配对事务、重置
  stats.py         只读汇总分析与 type-7 分位
  templates/index.html
tests/             unittest 测试（36 个，含改配 / 旧库迁移 / 端到端 HTTP 流程）
Dockerfile / docker-compose.yml / wsgi.py / requirements.txt
```

```bash
python -m unittest discover -s tests -v
```

覆盖：权重确定性与「邻户增删不影响本户」、Pois(1) 经验分布、分位插值、
汇总与逐户重算一致、原表只读、更正事务失败回滚、零权重轮跳过、空表原因提示、
完整 Flask 上传/更正/查询/重置流程；改配方面覆盖同单对调、失去伙伴自动解配、
四类整单退回、解配后同号改用独立权重、改分沿用在效配对、移除释放伙伴、
补录仅与空闲同号原表户自动配对、只重算变化户、旧库沿用旧结果与中断迁移自愈。

## 性能参考（实测，Python 3.11）

| 场景 | 耗时 |
| --- | --- |
| 3000 户上传（含 3000×1000 权重与两表汇总初始化） | 约 75 s |
| 1000 户上传（实测） | 约 18 s |
| 单户补录 / 改分 / 移除（实测） | 约 0.02 s |
| 单组改配，2 户变化（实测） | 约 0.04 s |
| 一次改配 300 组，399 户变化（实测） | 约 9.8 s（每户约 0.025 s） |
| 分析页查询（实测） | 约 0.007 s |

gunicorn 超时设为 120 s；更大规模数据集可在 compose 中调大 `--timeout`。
